## Vercel (recomendado) — deploy unificado

O projeto usa **um único projeto Vercel**: os 4 remotes são buildados e servidos como assets estáticos em subpastas (`/mfe-auth`, `/mfe-dashboard`, etc.) no mesmo domínio do shell.

### Deploy rápido (CLI)

```bash
# 1. Login na Vercel (apenas na primeira vez)
npx vercel login

# 2. Deploy de produção
chmod +x scripts/deploy-vercel.sh
./scripts/deploy-vercel.sh
```

Ou manualmente:

```bash
yarn build
npx vercel deploy --prod
```

### Variáveis de ambiente na Vercel

| Variável | Obrigatória | Descrição |
|----------|-------------|-----------|
| `AUTH_SECRET` | Sim (produção) | Gere com `openssl rand -base64 32` |

As URLs dos microfrontends (`NEXT_PUBLIC_MFE_*`) são **configuradas automaticamente** em `next.config.ts` a partir de `VERCEL_PROJECT_PRODUCTION_URL`. Não é necessário defini-las manualmente.

### Deploy via GitHub Actions

1. Crie um projeto na [Vercel](https://vercel.com) importando o repositório
2. Em **Settings → General**, copie `ORG_ID` e `PROJECT_ID`
3. Em **Settings → Environment Variables**, adicione `AUTH_SECRET`
4. No GitHub, adicione os secrets:
   - `VERCEL_TOKEN` — token em [vercel.com/account/tokens](https://vercel.com/account/tokens)
   - `VERCEL_ORG_ID`
   - `VERCEL_PROJECT_ID`
   - `AUTH_SECRET`
5. O workflow `.github/workflows/vercel-deploy.yml` faz deploy automático no push para `main`/`master`

### Verificar Module Federation em produção

Após o deploy, confirme que os remotes estão acessíveis:

```
https://seu-projeto.vercel.app/mfe-auth/remoteEntry.js
https://seu-projeto.vercel.app/mfe-dashboard/remoteEntry.js
https://seu-projeto.vercel.app/mfe-transactions/remoteEntry.js
https://seu-projeto.vercel.app/mfe-investments/remoteEntry.js
```

## Deploy alternativo — projetos separados

Cada remote pode ser um projeto Vercel separado (mais complexo):

- Root Directory: `remotes/mfe-dashboard`
- Build: `cd ../.. && yarn install && yarn workspace @flowtrack/mfe-dashboard build`
- Output: `dist`

Nesse caso, configure manualmente as variáveis `NEXT_PUBLIC_MFE_*` com as URLs de cada projeto.

## CI/CD

GitHub Actions em `.github/workflows/ci.yml`:

- Lint
- Testes
- Build
- Docker image

## Produção

Em produção, cada remote serve `remoteEntry.js` com CORS habilitado. O shell carrega os módulos em runtime via URLs configuradas.
